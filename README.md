# ChatGPT 问题导航 2.5.0

适用于 Chrome / Microsoft Edge 的本地扩展，提供接近 Codex 对话导航的短横线目录、问题与回答预览、本地书签和快速定位。

## 功能

- **选择保存文件夹**：可把导航记忆保存到插件所在文件夹或其他磁盘。通过浏览器文件夹选择器授权后，目录 JSON 写入所选位置的 `navigator-data` 子文件夹；现有记忆自动迁移，核验后清除浏览器中的旧目录正文。授权失效时会停止保存并提示重新授权。
- **本地导航记忆**：第一次读取后自动保存每个对话的问题目录、预览摘要和已知定位信息；刷新、关闭浏览器或切换回来时先恢复目录。完整目录命中记忆时只核对网页现有数据，不重新读取全部旧历史。新增消息及完整分支更新会刷新记忆；手动滚动补全的目录也能保存。
- **数据优先的目录**：从网页自身已收到的当前对话响应、初始化数据或已挂载的 React 对话状态建立索引，只选择当前分支。支持由精确对话查询键标识的分页缓存；新消息到来时保留已经合并的历史。完整数据可用时，直接显示全部问题，不滚动聊天收集目录。
- **不滚动正文的历史读取**：如果网页只加载了最后几条消息，优先复用当前对话已经提交的原生分页回调，也兼容历史占位符的观察回调。同一观察器跨页复用时，只有索引取得进展才再次触发；等待中的分页不重复调用。读取可暂停、恢复，失败会停止。加载提示暂时消失不会误报完成。
- **问题与回答预览**：悬停约 150 毫秒显示问题、对应回答摘要和附件名称，预览内容按纯文本显示。
- **本地书签**：在预览卡片中点击书签按钮；横线旁会显示书签圆点。刷新后仍可恢复，按对话分别保存。
- **点击定位**：优先按真实消息标识绑定气泡，或调用页面可用的原生消息定位动作并等待挂载；否则进行有限次区间定位，核验气泡后校正位置。点击不会从头逐屏遍历整段聊天；失败保留目录并恢复阅读位置。定位期间收到历史分页或状态更新不会取消当前点击。重复的“继续”保留为独立条目。
- **快速浏览**：`Alt + ↑` / `Alt + ↓` 切换上一个 / 下一个问题；按住鼠标在横线之间拖动可快速浏览，松开后定位选中的问题。
- **Codex 风格动效**：横线平时为 6 像素，悬停时展开到 26 像素，相邻三条依次为 20 / 14 / 10 像素；约 160 毫秒的弹性过渡。行高保持 10 像素，点击区域不移动。预览卡片随选中行移动，拖动时即时跟随。支持深色主题和系统减少动态效果设置。
- **手动兼容补全**：网页不提供可兼容的数据或历史加载器时，点击下方 `↻` 重试读取；`Shift + 点击` 才启动滚动补全，结束后恢复阅读位置。不会默认遍历滚动整段聊天。

## 安装或更新

1. 解压发布包，或使用本项目文件夹。
2. 在 Edge 打开 `edge://extensions/`，Chrome 使用 `chrome://extensions/`。
3. 开启「开发人员模式」，点击「加载解压缩的扩展」，选择包含 `manifest.json` 的文件夹。
4. 已安装的用户点击扩展卡片上的「重新加载」。2.0 新增 `storage` 权限，用于在本地保存书签标识。
5. **更新后刷新 ChatGPT 聊天页面一次**。首次使用记忆仍需读到该对话的目录，此后再次进入会直接恢复。2.5 无新增清单权限；自选文件夹需要在浏览器选择器中授权。

安装或更新后会尝试为已打开的 ChatGPT 标签页注入导航；点击浏览器扩展图标也可重新扫描。站点访问权限应允许在 `chatgpt.com` 使用。

## 使用

每条短横线代表当前分支的一条用户提问。悬停可预览问题与回答；点击横线或预览卡片中的问题可跳转。预览卡片中的书签按钮只切换收藏，不会触发跳转。

记忆默认自动启用。右键导航下方的数字或 `↻`，可在面板底部「本地导航记忆」中清除此对话或全部目录记忆，书签保留。清除后，本次打开期间暂停自动保存；点击「恢复保存记忆」或下次进入对话后重新启用。

### 保存到 D 盘或插件文件夹

1. 右键导航下方数字或 `↻` →「记忆保存位置」；也可在浏览器扩展管理页打开本扩展的「扩展选项」。
2. 点击「选择保存文件夹」，在系统窗口中选中插件所在的 `ChatGPT-Navigator` 文件夹，并允许写入。
3. 记忆将保存在 `ChatGPT-Navigator\navigator-data\conversation-*.json`。迁移完成后刷新聊天页面。

浏览器不会允许扩展仅凭绝对路径静默写入，必须由用户在文件夹选择器中授权。[File System Access 官方说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。文件夹授权及少量设置仍由浏览器保管，目录正文保存在选择的磁盘上；书签继续保存在浏览器中。

移动文件夹或授权失效后，可以重新选择或点击「重新授权此文件夹」。文件夹模式不会在失败时自动退回浏览器保存。点击「使用浏览器存储」可复制回浏览器，原文件夹中的 JSON 保留。`navigator-data/` 已加入 Git 忽略规则，发布包不包含个人记忆文件。

最多保存最近 50 个对话，总容量约 6 MiB，单条不超过 1 MiB；90 天未使用的记录会失效，并在下一次读取或写入时清理。超出容量时优先保留最近使用的对话。存储不可用时，当前页面导航仍可使用。

如果仍然只有几条记录，**右键导航下方的数字或 `↻`，选择面板内的「复制诊断」**。诊断会显示内容脚本 / 主页面脚本版本、索引数量、数据完整性、响应解析次数、已识别加载器和已触发分页数；不包含对话网址、ID、聊天原文、附件名或认证信息。它不会额外发起历史请求，便于定位真实页面的兼容问题。

导航下方的按钮保持与导航栏同宽：

| 显示 | 含义 |
| --- | --- |
| 数字，例如 `40` | 当前问题数量；点击刷新目录或重新补全 |
| `↻` | 点击重试历史读取；`Shift + 点击` 使用滚动补全 |
| `Ⅱ` | 正在读取或补全；点击暂停 |
| `…` | 正在定位；点击取消 |

将鼠标停在按钮上可查看具体状态。默认复用网页分页流程读取历史，不遍历滚动正文；`Esc` 或点击 `Ⅱ` 可暂停，点击 `↻` 可恢复。手动兼容补全会滚动当前聊天并触发网页加载历史，结束后恢复阅读位置；滚动、输入或点击页面会暂停这种滚动补全。每次读取最多约 90 秒；网页报错或长时间没有进展时停止。

## 数据与隐私

- 扩展只在 `https://chatgpt.com/*` 和 `https://chat.openai.com/*` 生效。
- `page-bridge.js` 在网页主上下文观察现有 fetch、Response.json 和 XHR 的当前对话 JSON，不读取登录令牌、Cookie、请求认证头或认证接口。
- `page-state.js` 读取已提交组件的自有数据字段、Hook 和 Context，兼容类实例与 Map 缓存。图自身没有 ID 时，只绑定直属 `conversation` 或精确匹配的对话查询键，不向任意缓存传播身份。不会执行 getter、普通 store 方法、提交或重新生成动作。仅允许调用明确绑定当前对话、有分页状态的历史回调，及明确命名的消息定位动作。
- `history-loader.js` 复用页面可用的历史分页回调；也会在初始化时记录原生历史占位符及观察回调。网络请求和认证由网页已有代码执行；扩展不自行构造历史 API 请求，不触发图片等无关观察器。
- 仅向扩展传递消息标识、当前分支关系、用户问题、可见回答文本和附件名称；不传递系统消息、隐藏分析、附件下载地址或认证字段。
- 导航记忆默认保存到扩展的 `chrome.storage.local`；选择文件夹后，后台通过用户授权的目录句柄读写 JSON，浏览器仅保留位置设置及授权句柄。按站点和对话 ID 隔离，不上传外部服务，也不使用浏览器云同步。
- 目录记忆保存消息标识、分支结构、问题摘要（最多约 200 字符）、回答摘要（最多 800 字符）、附件名称及已知定位信息。只保留当前索引分支，不保存认证字段、隐藏分析、系统消息、附件下载地址、图片内容或完整聊天原文。摘要可能包含对话中的个人内容，可从面板清除。
- 书签与目录记忆分别保存。书签只保存对话 / 消息标识，缺少真实消息标识时使用文本指纹和出现次序作为兼容标识；清除目录记忆不会清除书签。
- 自动历史读取、正常浏览或兼容补全时，ChatGPT 本身会请求较早消息。暂停不能撤销已发出的那一页请求，但不会继续发起下一页。

## 工作方式

```text
再次进入 → 读取扩展本地目录记忆 → 立即显示问题 → 后台核对当前网页数据
                                            ↓
                                    更新或补全后保存记忆

网页已有的当前对话数据 → 当前分支的问题索引 → 导航 / 回答预览 / 书签
                              ↓ 点击
                    绑定真实消息 → 定位区间 → 核验气泡位置

仅有部分历史 → 网页自身分页加载 → 合并消息图 → 完整目录
加载器不可用 → 当前页面扫描 → Shift+点击后才滚动补全
```

网页主上下文中的桥接模块与扩展的隔离上下文通过带当前会话标识的消息通道通信。扩展收到数据后再次校验对话 ID 和结构；导航与书签存储保留在扩展隔离上下文中。

## 官方实现的参考范围

[OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 提供按轮次分页的 `thread/turns/list`、按消息分页的 `thread/items/list`，并支持消息 ID 锚点。这说明历史数据可以独立于当前屏幕上的消息读取。本扩展参考这种数据与渲染分离的设计建立目录，结合 ChatGPT 页面自己的分页及定位能力。

该文档没有披露桌面端右侧导航的前端实现；这里不是复用 Codex 的私有导航 API，也不将上述接口用于读取 ChatGPT 网页对话。

关于「记忆」，官方文档可以确认 Codex 会持久保存会话日志，再通过接口读取已保存的轮次和消息；没有说明右侧导航是否独立持久化目录缓存。本扩展的本地目录记忆是针对浏览器扩展限制的实现选择。

## 限制

- 这是独立扩展，并非 OpenAI 官方产品；Codex 的内部虚拟列表 API 不能直接用于 ChatGPT 网页。离屏消息的定位仍受网页加载和渲染机制影响。
- 无滚动补全需要网页提供可识别的分页回调，或历史占位符与 IntersectionObserver 分页流程，同时需要能解析返回的消息图或组件状态。网页更换机制或缓存为不可访问的私有字段时，可能需要刷新或使用手动滚动补全；无法突破网站本身的历史访问限制。
- 原生消息定位只在页面暴露兼容动作时可用；其他页面使用有限次区间定位。目标暂时无法挂载时会停止并恢复阅读位置，点击不会自动转为整段滚动搜索。
- 本地记忆可以先恢复目录和摘要，但不能让网页尚未加载的聊天正文立即出现。旧消息定位仍依赖网页自身的加载与渲染能力。首次尚未读全的目录会继续补全；只读到部分最新消息时无法确认所有远端删除或编辑，完整新数据到达后才会校正。
- 页面没有消息 ID，且上下文中存在多个完全相同的问题时，定位需要更多前后文；扩展不会仅凭相同文本猜测目标。
- 数据尚未更新时，新发送的问题先由页面扫描补入。切换分支或编辑很早的消息后，若目录暂未更新，可刷新聊天页面重新读取数据。
- 兼容模式只能读取网页允许加载的历史；已删除或无法通过网页加载的消息不能定位。
- 书签通常按真实消息 ID 恢复；页面完全没有稳定标识时，编辑问题或改变重复问题的顺序可能影响兼容书签的恢复。

## 文件

- `manifest.json`：站点、权限及主 / 隔离上下文的加载顺序。
- `background.js`：安装、更新和点击扩展图标时注入。
- `folder-storage.js`：后台 / 设置页的文件夹授权、JSON 读写、迁移核验、保留策略及存储切换。
- `settings.html`、`settings.css`、`settings.js`：保存位置选择与重新授权。
- `conversation-model.js`：纯数据解析、当前分支选择和问题 / 回答配对。
- `navigation-memory.js`：本地目录记忆的结构校验、摘要裁剪、保存恢复、容量淘汰和清除。
- `page-state.js`：从已挂载组件的现有状态查找当前对话。
- `history-loader.js`：在不遍历滚动正文的情况下复用原生历史分页流程。
- `page-bridge.js`：只观察网页现有响应及初始化数据。
- `content.js`：导航、预览、书签、键盘、拖动、定位和兼容扫描。
- `icons/`：扩展图标。

## 开发验证

单元测试：

```cmd
node --test tests/background.test.cjs tests/conversation-model.test.cjs tests/page-bridge.test.cjs tests/page-state.test.cjs tests/navigation-memory.test.cjs tests/folder-storage.test.cjs
```

浏览器测试需要已有的 Edge 和 Playwright：

```cmd
npm install --no-save playwright-core
node tests/content.browser.cjs
node tests/data.browser.cjs
node tests/native-history.browser.cjs
node tests/navigation.browser.cjs
node tests/memory.browser.cjs
node tests/extension.browser.cjs
```

可用 `EDGE_PATH` 和 `PLAYWRIGHT_MODULE` 指定现有安装路径。浏览器回归使用模拟聊天页面，不读取个人对话。

- `content.browser.cjs`：60 条虚拟问题、30 条分页历史、消息去重、节点复用、路由切换、取消定位及几何稳定性。
- `data.browser.cjs`：40 条数据索引、延迟挂载的 React 缓存、无滚动/无新增请求、悬停横线动效、减少动态效果、问题 / 回答配对、附件、同文问题、分支切换、无 ID 的新消息、流式预览、书签、快捷键和拖动。
- `native-history.browser.cjs`：仅提供末尾 5 条记录时，通过网页原生加载器分 7 页读取 40 条，验证不调用正文滚动、同一观察器复用、无占位符的分页回调、暂停恢复、失败停止及不触发无关观察器。
- `navigation.browser.cjs`：真实消息 ID 的原生异步定位、定位中更新数据、目标未挂载时有限停止、保留目录并恢复阅读位置，禁止从头遍历正文。
- `navigation-memory.test.cjs`：跨实例恢复、当前分支与敏感字段过滤、摘要裁剪、过期、容量淘汰、清除与书签隔离。
- `folder-storage.test.cjs`：在工作区 D 盘测试目录中读写真实 JSON，验证迁移、源文件保护、授权失效、失败保留原数据、过期淘汰及路径约束。
- `memory.browser.cjs`：刷新恢复目录和预览、部分数据不覆盖完整记忆、新消息和分支更新、手动目录恢复、清除与恢复保存、存储失败兼容。
- `extension.browser.cjs`：真实 MV3 扩展、跨上下文通信、分页与目录记忆；设置页使用真实 OPFS 句柄代替系统选择器，验证句柄持久化、迁移、后台文件读写、切回浏览器及文件夹清除。系统文件夹授权仍需用户手动完成。测试配置生成在 `test-results/`。
